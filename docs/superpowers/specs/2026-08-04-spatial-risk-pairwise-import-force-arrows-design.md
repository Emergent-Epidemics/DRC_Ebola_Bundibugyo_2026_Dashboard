# Spatial-risk arrows driven by Bayesian pairwise import-force

**Date:** 2026-08-04
**Repo:** BDBV2026-Epidemic_Dashboard
**Status:** Design approved, pending spec review

## Context

On the Spatial Risk tab (`epi-trends` view = `spatial-risk.html`), selecting a health
zone draws curved inflow arrows from other zones. Today those arrows come from the
Flowminder mobility catalog (`PAYLOAD.flow_catalogs.flowminder_latest`), and their
width is set by `importationPressure()` in `Scripts/assets/engine.js` — the number of
**confirmed cases in the origin zone**, normalized against the selected zone's maximum
(`renderFlowArcs`, engine.js:634–726).

A new Bayesian analysis output now exists and is already published to the sensitive-data
repo by CI: `outputs/<date>/spatiotemporal/reports/bayes_pairwise_import_force.csv`
(generated by `bayes_pairwise_import_force()` in BDBV2026-Analysis). It decomposes the
featured invasion model's per-week destination hazard into directed origin→destination
contributions. We want the arrow widths to reflect this model output instead of the raw
confirmed-case heuristic.

The spatiotemporal Bayes output is **already ingested** for the ranked table + choropleth
on this same tab: `load_invasion_risk_estimates()` (data_sources.py:1433) reads
`<date>/spatiotemporal/key_outputs/bayes_risk_scores_all_zones.csv` into
`PAYLOAD.invasion_risk`. Only the arrows are still on the old metric.

## Goal

On the `epi-trends` view, draw inflow arrows from the pairwise import-force table and
scale their width by each origin's contribution to the selected zone's invasion hazard,
falling back to today's behavior when the new data is absent. No change to the snapshot
(`current-snapshot`) view's arrows.

## Pairwise CSV (input)

Columns: `origin_zone, dest_zone, horizon, w_ji, source_origin, import_force, foi,
dest_import_force_total, dest_hazard_week, share_of_dest, origin_province, dest_province`.

Verified identities (exact across all rows):
- `import_force(j→i) = w_ji · source_origin(j)`
- `dest_import_force_total(i) = Σ_j import_force(j→i)` = Λ_i
- `share_of_dest = import_force / dest_import_force_total`
- `foi = share_of_dest · dest_hazard_week = β · import_force`

Zone names in `origin_zone`/`dest_zone` are canonical `nom` strings — verified to match
the dashboard's 519 `nom` keys exactly (0 mismatches), so **no name aliasing is needed**.
Horizons present: 1 and 2.

## Design decisions

1. **Width metric = `foi`** (contribution to the selected zone's weekly invasion
   probability), shown in the tooltip.
2. **Normalization = per-zone**, against the selected zone's own maximum `foi`.
   - Consequence, explicitly accepted: under per-zone normalization `foi`, `share_of_dest`,
     and `import_force` yield *identical* widths — they differ only by the per-destination
     constant `H_i = β·Λ_i`, which cancels: `foi_ji / max_k foi_ki = share_ji / max_k share_ki`.
     Cross-zone magnitude is intentionally discarded in favor of a clean per-zone display
     (every selected zone's top source renders at full width). The metric choice therefore
     affects only the tooltip value, not the width.
3. **Pixel mapping = sqrt-compressed:** `weight = 1 + 4·√(foi_ji / max_i foi)` — same shape
   as the existing snapshot-view `flowArcWeight()`, keeps mid/smaller sources legible.
4. **Arrow set = pairwise sources only:** draw one arrow per origin present in the pairwise
   table for the selected zone (origins that actually contribute case-importation pressure).
   Not the full mobility inflow set.
5. **Horizon = 1**, matching the invasion-risk table/choropleth already on this tab
   (`load_invasion_risk_estimates` prefers `horizon == 1`).
6. **Fallback:** if `PAYLOAD.import_force_pairwise` is null or has no entry for the selected
   zone, arrows fall back to the current `importationPressure` (confirmed-cases) path,
   unchanged. Guarantees no regression on older builds / missing data.

## Architecture

### A. Python build — new loader + payload key

New loader in `Scripts/common/data_sources.py`, `load_bayes_import_force_pairwise()`,
modeled on `load_invasion_risk_estimates()`:

- Locate the CSV via the existing newest-date resolver used for invasion risk
  (`_latest_spatiotemporal_key_outputs_dir`), then read its sibling
  `../reports/bayes_pairwise_import_force.csv` from the **same date folder** the
  invasion-risk table uses (keeps arrows and table in sync).
- Filter to `horizon == 1`.
- Group rows by `dest_zone`; within each dest, sort origins by `foi` descending and keep
  **all** sources (first iteration — no cap). The generator already emits only
  positive-import-force edges, so there is no zero padding to drop.
- Emit a sparse structure keyed by `nom`:
  ```
  in_by_dest = { dest_nom: [ [origin_nom, foi, share_of_dest], ... ], ... }
  ```
- Return dict:
  ```
  { "in_by_dest": {...}, "horizon": 1, "beta": <derived>,
    "cutoff_date": <same as invasion_risk>, "yyyymmdd": <date folder> }
  ```
  The pairwise CSV has **no `method` column** — the featured-model name is not available
  here (it lives in `bayes_risk_scores_all_zones.csv` and already reaches the payload via
  `PAYLOAD.invasion_risk[*].method`, which the legend/tooltip can reference if desired).
  `beta` is derivable as `foi / import_force` from any row (a single global constant);
  it is informational only and not required for rendering. Both are optional.
- On any failure (dir/file absent, empty) return `None` (loaders in this codebase warn and
  yield null; missing inputs are tolerated by the build).

Register a new top-level key `import_force_pairwise` in `build_shared_payload()`
(`Scripts/common/payload.py`) return dict.

### B. engine.js — arrow rendering

- Near the other payload reads, add `const IMPORT_FORCE = PAYLOAD.import_force_pairwise || null;`
- In `renderFlowArcs(hubNom, layer)`, on the `useImportPressure` (epi-trends) branch:
  - If `IMPORT_FORCE && IMPORT_FORCE.in_by_dest[hubNom]` exists → build arrows from that
    edge list (pairwise-only set). For each `[origin, foi, share]`:
    - `maxFoi = max foi over this hub's edges` (render-time, mirrors current `maxMetric`).
    - `weight = flowArcWeight(foi, maxFoi)` using the existing sqrt helper
      (`1 + 4·√(foi/maxFoi)`), or an equivalent inline sqrt on the normalized fraction.
    - Draw origin→hub polyline (unchanged geometry/color/chevron); tooltip: origin → zone,
      `foi` (formatted) and `share_of_dest` as a percentage. Tooltip/legend stay generic —
      the featured model is not named.
  - Else → existing confirmed-cases `importationPressure` path, unchanged.
- Snapshot (`current-snapshot`) view path untouched.

### C. Legend

Update the flow-arc legend text (`Scripts/common/chrome.py:302`) to describe the new metric:
line width ∝ each origin's contribution (`foi`, h=1) to the selected zone's weekly invasion
probability from the Bayesian import model (Flowminder mobility × modelled incidence),
normalized within the selected zone. Keep wording accurate about per-zone normalization.

## Data flow

```
BDBV2026-Analysis run_all → outputs/reports/bayes_pairwise_import_force.csv
  → (CI) published to BDBV2026-Processed_Sensitive_Data/outputs/<date>/spatiotemporal/reports/
  → (dashboard build) DASHBOARD_PLOTS_DIR → load_bayes_import_force_pairwise()
  → PAYLOAD.import_force_pairwise → engine.js renderFlowArcs → arrow widths
```
